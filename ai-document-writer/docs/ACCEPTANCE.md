# V2 文档助手：自动验收与业务验收方案

本方案区分 CI 自动验证与真实业务验收。CI 使用合成 DOCX 与模拟模型响应；不会调用 DeepSeek，不消耗真实 API 费用。

## 一、CI 自动验收

运行：

    dotnet test ./backend/AiDocumentWriter.Tests/AiDocumentWriter.Tests.csproj -c Release
    node --test ./frontend/tests/annualGuard.test.mjs

### 六个月的合成场景

| 月份 | WMS 数据库迁移阶段 | 独立巡检次数 |
| --- | --- | ---: |
| 1月 | 方案设计 | 20 |
| 2月 | 接口测试 | 25 |
| 3月 | 最终验收 | 30 |
| 4月 | — | 20 |
| 5月 | — | 25 |
| 6月 | — | 30 |

AcceptanceFlowTests 生成 6 篇 DOCX，通过真实 HTTP 接口逐篇解析，使用模拟模型响应完成事实提取、事项归并、正文生成与 Word 导出。

预期提取 9 条可定位的工作事实，将迁移的三个阶段关联成一项持续工作，并在模拟口径一致的情况下累计巡检 150 次。使用往年 DOCX 作为模板时，不得把旧正文带入结果。

另检查：服务器模式不能持久化页面 Key；缺少客户端头的写请求返回 403；年度模式中仅参考格式的文件不能贡献事实材料；关键冲突须包含人工处理依据；一般疑问必须保留待核验提示。

上述测试验证程序的数据流、协议、可追溯性和格式处理；**模拟模型得到的固定答案不能证明真实模型可准确分析任意月报。**

## 二、真实业务验收（需要授权材料与真实 Key）

建议准备经过脱敏和授权的 6～15 篇月报或季报，以及一份仅供参考排版的往年 DOCX。样本应覆盖跨月项目进度、周期性工作量、重复记载、累计数字、百分比、矛盾状态以及标题和表格。

1. 上传材料后核对月份、用途及文件数量；确认仅风格参考文件不会进入事实提取。
2. 逐条核对来源文件、证据原文、进度状态和数字，统计漏提及错提。
3. 检查同一项目的多月阶段是否合并；累计百分比不能直接求和。
4. 仅在统计口径相同且不重复时相加工作量；无法确定时保留待核实。
5. 人工处理关键冲突后再生成，检查最终总结没有凭空补造的项目、数据与完成状态。
6. 将结果导出 DOCX，使用 Microsoft Word 与 WPS 核对页面设置、标题、段落、表格和页眉页脚；检查不含往年的正文和过期日期。
7. 测试取消、错误 Key、网络中断和长材料的恢复提示，记录实际 Token 及 API 开销。

### 验收门槛

- 关键事实必须能找到来源；没有证据的结果不得写成确定性成果。
- 未确认的关键冲突不得形成确定性结论。
- 仅参考格式的文档不得贡献本年度事实。
- DOCX 可在 Word/WPS 打开并编辑，常见样式符合模板；不承诺任意复杂图文混排的像素级复制。
- 桌面版只在本机提供服务，公网部署须有认证、HTTPS 与速率限制。

**尚未执行**：真实 DeepSeek API 的准确性和费用测试、真实业务材料验收、Word/WPS 模板人工视觉复核。不能将 CI 通过等同于全部业务验收。

## 三、不属于本轮的能力

PDF/OCR、任意复杂模板精确复刻、多租户权限、超出上下文上限的自动层级归并，均需单独设计与验收。
