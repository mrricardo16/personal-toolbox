# 中文写作质量 A/B 验收方案

## 目标与前提

在本地写作工具中对照 **A：经典 Prompt** 和 **B：同 Prompt + 经审核的中文写作 Skill**。用户点击“A/B 对照”会针对同一套材料依次发起两次 API 请求，并将两个结果保存为会话内快照。

A/B 测试不是免费操作；模型每次生成具有随机性，不能仅用一对文章证明 Skill 有效。建议在相同模型、参数、输入及不进行二次审校的条件下，多次重复样本，并通过盲评记录。

## 合成测试集

`evaluation/cases.json` 提供 20 组原创的虚构业务案例，包含工作总结、报告、会议纪要、通知、方案和润色，覆盖：
- 独立业务量与累计口径；
- 进度比例不可相加；
- 同一成果在多月出现；
- 计划、进行中、完成与验收结果；
- 会议争议与待决定事项；
- 专有名词、数字、时间范围的保真。

每条测试包含 `mustContain` 和 `mustNotContain`，只用于**硬约束预检**，绝不能代替人工的结构、自然度和文风评价。

## 命令行复跑

在新版服务运行于本机时，在项目目录执行。先在前端目录运行一次 npm run build，以生成原版规则模块。脚本默认只打印计划调用数。

```powershell
node evaluation/run-writing-ab.mjs --case S01 --case R01 --repetitions 2
node evaluation/run-writing-ab.mjs --url http://127.0.0.1:5080 --case S01 --case R01 --repetitions 2 --run --output .\ab-20261118
```

`--url` 应填写实际的本机服务地址。`--run` 会产生真实模型调用费用并写入一个新目录。使用服务端配置的 Key，或提前在进程环境中设置 `AIWRITER_EVAL_API_KEY` 供单次会话使用。结果 JSON 中不包含 Key。没有独立 Skill 的文种会列入 `skipped`。

经典 Prompt 和 Skill 使用同样的模型、参数、写作要求和事实材料，关闭自动审校。仅将匿名样本 JSON 发给盲评人，评分完成后用 `blind-key.json` 还原分组。硬约束字符串结果供人工复查。旧 HTML 须用同样输入及模型独立运行，可作为额外对照。

## 人工评分（每篇 100 分）

| 指标 | 权重 | 评价办法 |
| --- | ---: | --- |
| 事实准确与无编造 | 40 | 逐条核对来源、数字、状态、主体；关键事实编造直接判不合格 |
| 信息覆盖与具体程度 | 20 | 是否保留来源中对读者有价值的做法、进展和限制 |
| 结构与叙事主线 | 20 | 段落层级合理、重点突出、不机械堆砌 |
| 中文表达自然度 | 10 | 套话、重复、AI 式固定句式、语体不匹配程度 |
| 后续改稿成本 | 10 | 达到可用稿需要的人工修改次数与耗时 |

录入时应隐藏 A/B 的来源标签，让熟悉材料的同事盲评；每个案例至少评估两次，记录平均差异和主观分歧。

## 修订能力验收

| 场景 | 通过要求 |
| --- | --- |
| 只修改选中的第二段 | 第一段及第三段逐字符不变 |
| 全文修改 | 输出候选版，未点击“采纳”前当前正文不变 |
| 用户指定项目名和数字为保护项 | 修订候选不得删除原文中的保护项 |
| 修改到一半请求失败 | 已有稿件和版本记录保持可用 |
| 修改候选生成后用户手工改动正文 | 不允许直接采纳过期候选覆盖新修改 |
| 审校 | 初稿、审校稿是独立历史版本 |
| A/B 比较 | 两版本可切换、并排比较；实际调用次数有清晰提示 |
