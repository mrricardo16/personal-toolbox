# TV Browser Lite｜测试计划与验收标准

- 状态：测试计划持续维护；**本轮新增功能尚未完成电视实机验证**
- 主测环境：小米 Android TV + GeckoView 自带引擎（具体 Android SDK、ABI、机型待记录）
- 产品目标：像 TV Bro 一样直接输入任意 HTTP/HTTPS 网站，在浏览器内部展示页面

## 1. 环境基线

测试前记录以下字段，不允许凭“其他 APK 安装成功”推断：
- 电视品牌/型号、Android 版本、API level、`ro.product.cpu.abilist`；
- 安装 APK 的文件名/版本、包名、签名 SHA-256、GeckoView 版本和 ABI；
- 电视 IP、网关、连接方式；电脑 Nginx IP/端口（可能变化）；
- 目标站点前端构建版本、是否需要登录、测试日期和网络情况。

以上局域网 IP 为当前环境**示例值**，不可访问时记录网络前置条件，不把不可执行标记 PASS。

## 3. RSS 4.1 专项对照（非通用浏览器的唯一准入条件）

测试地址：`http://192.168.12.195:8221/`

| ID | 步骤 | 判定 |
| --- | --- | --- |
| TVB-RSS-001 | 从地址栏进入 RSS 首页 | 记录 HTML、JS、CSS 是否能加载，是否仍残留静态 loader |
| TVB-RSS-002 | 与电视 TV Bro、Windows Chrome 同地址对照 | 记录引擎/版本/现象，避免只依据“空白”猜测根因 |
| TVB-RSS-003 | 登录与首次路由跳转（取得测试账户后） | 显示实际成功/失败与 HTTP/API 证据 |
| TVB-RSS-004 | 重新加载 / 清站点数据 / 冷启动 | 检验问题是否稳定复现与可恢复 |
| TVB-RSS-005 | 出现原始静态 loader 长时间不消失 | 记录网络与脚本证据；不能直接将其认定为 GeckoView 错误 |

已有源码检查发现 `config.js` 的潜在加载竞态与现代 JS 兼容风险；即使 GeckoView 避开系统旧引擎，**网页自身问题仍可能独立存在**。

## 4. 负向与安全用例

| ID | 场景 | 期望 |
| --- | --- | --- |
| TVB-S001 | 站点请求摄像头/麦克风/定位 | 默认拒绝或明确提示，未经允许不授予 |
| TVB-S002 | 不合法 HTTPS 证书 | 不自动忽略 |
| TVB-S003 | 网页触发外部 intent / 非网页 scheme | 不自动执行危险意图 |
| TVB-S004 | URL 中含 Token、查询密钥 | 诊断日志不能泄漏 |
| TVB-S005 | 页面进程崩溃 | 应用能返回可理解提示并允许重试 |
| TVB-S006 | 弱网/频繁切换 Wi-Fi | 不无限重载，不损坏历史 |
| TVB-S007 | 无可用 DNS 但直连局域网 IP 可用 | 分开判断 DNS 与 TCP 故障 |

## 5. 通过标准与缺陷优先级

- **阻断（Blocker）**：APK 无法安装/启动、GeckoView 不可用、地址栏不可输入、HTTP/HTTPS 均无法导航。
- **严重（High）**：主页面持续崩溃、导航经常失效、可绕过证书错误、凭据被写入日志。
- **一般（Medium）**：部分网页交互异常、特定设备的软键盘/焦点问题、可恢复的兼容性偏差。
- **优化（Low）**：图标/文案/布局细节、非核心功能缺失。

第一版验收：**所有适用的 TVB-001～020 用例通过且无 Blocker/High 缺陷**；对不适用或无法执行用例必须说明原因与证据。RSS 专项结果单独报告，不得把网站自身 JS 错误伪装为浏览器验收成功或失败。
