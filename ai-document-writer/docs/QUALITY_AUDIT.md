# AI 文档助手质量审计

审阅基准为远端 main 提交 `7c0f2f5ce9152ed9a524c483987a793ff632ab47`，客户端版本 V2.2，发布版本 0.3.0。本地旧工作树只有单文件版。旧版 HTML 与基准提交中的旧版文件是相同的 Git blob `d5b7e7dd81bf792ae32597bc19f71aa26c7d55bb`。

| 缺陷 | 基准上发现的证据 | 验证边界 |
| --- | --- | --- |
| BUG-01 经典写作质量 | 原版规则来自相同 HTML，但默认模型、策略及审校开关与请求包装有差异。20 条样本验证只检查题库形状和文种覆盖。 | 质量回归尚需获得可比较的真实模型输出和盲评。 |
| BUG-02 跨月归并 | `AnnualWorkflow.MergeAsync` 只修整成员 ID、处理遗漏和引用匹配状态。不同项目并组或同项目阶段拆组可能进入台账。 | 模拟响应覆盖确定性修复。真实月报的误分率仍待测定。 |
| BUG-03 统计口径 | `AnnualFact.NumericEvidence` 与 `AnnualGroup.Metrics` 原为自由文本，服务端直接使用模型给出的合计。固定模拟响应声称 150 次，程序没有进行计算。 | 将合计改为 777 次的测试复现问题。累计快照、百分比、重叠月份和混合单位需要保守处理。 |
| BUG-04 写作要求贯穿 | 年度提取不传写作范围，归并和提纲只带任务文本，年度审校只带台账与稿件。常规审校遗漏篇幅、受众、附加要求等。 | 模拟请求记录复现。需要用同一工作流快照进行复测。 |
| BUG-05 指令与来源隔离 | 年度普通疑点说明被原样追加到正文。向模拟审校响应放入仅风格资料的历史数据时，基准版本会直接采用。 | 已确认确定性泄漏入口。对改写后的模型幻觉仍需进行真实质量评估。 |
| BUG-06 连续修订 | 第二轮能使用上一轮采纳稿，编辑正文后过期候选会阻断。候选元数据读取了页面当前控件，迟到的自动审校还可能覆盖已采纳稿。服务端只检查显式保护项是否仍出现。 | 通过模拟响应复现元数据串位、现稿被覆盖和无源数字进入候选稿。 |

审阅入口包括 `App.vue`、`AnnualWorkspace.vue`、`RevisionWorkspace.vue`、`AnnualWorkflow.cs`、`WritingRevisionService.cs`，以及 `Program.cs` 的 `/api/llm/chat`、`/api/annual/extract`、`/api/annual/merge` 和 `/api/writing/revise`。应用的各阶段经 `DeepSeekClient` 请求模型服务。

基准提交的 GitHub Actions 构建 #44041804908 已通过，记录显示前端 11/11，后端 19/19，并构建及启动验证了 Windows / Linux 包。该 CI 使用模拟模型，已存在的 A/B 工具和合成案例不能作为真实写作质量结论。

## 真实写作复测

先用同一个授权模型、参数和材料采样新版经典 Prompt 与 Skill 两条路径。记录是否启用审校，与旧单文件版本比较时应固定同样的模型、审校开关和文种。按事实准确、信息覆盖、结构、表达自然度和人工改稿耗时记录盲评结果。测试样本和评分要求见 [WRITING_EVAL.md](WRITING_EVAL.md)。

年度真实材料还需覆盖同名不同项目、别名同项目、重复成果、同月多文档、跨月累计快照、百分比、口径变化和关键冲突。完成自动测试及打包仅能证明指定行为和启动路径可运行。
